# LANCEMENT DE LA PREMIÈRE APP — checklist

## Avant de commencer（une fois）
- [ ] config/api-keys.env rempli + install-api-keys.ps1 exécuté + terminal rouvert
- [ ] Compte expo.dev créé（gratuit）— nécessaire pour les builds
- [ ] Compte Google Play Console（25 $）— nécessaire pour publier（pas pour tester）
- [ ] Git installé, repo GitHub privé pour l'app
- [ ] Les skills Expo installées（npx skills）et le MCP open-design chargé（redémarrage）

## Le déroulé（ce que fait l'utilisateur, rien de plus）
1. "SCAN <marché>" → je lis le rapport → je choisis la niche → "ok"
2."DÉCORTIQUE <2-3 apps leaders>" → je lis les CARTE.md → je donne mon avis → "ok"
3."FORGE <nom-app>" → je valide à chaque arrêt ：PRD（ce que l'app promet）→
   cahier des charges → plan technique → liste des tâches. Répondre "ok" ou dire ce
   qui ne me plaît pas, en français。
4."STYLE <nom-app>" → je choisis parmi 2-3 directions visuelles montrées en images。
5."BÂTIT <nom-app>" → l'agent code seul. Je n'ai rien à faire. S'il bloque  ẟ3 fois
   sur le même point, il me demande。
6."TESTE <nom-app>" → l'agent teste sur émulateur, puis m'envoie le fichier à
   installer sur mon téléphone（APK）+ le modèle RETOUR-UTILISATEUR à remplir。
7. Boucle ：je teste, je remplis le modèle, l'agent corrige, je re-teste。
8."EMBALLAGE <nom-app>" → je valide les visuels et textes du store。
9."LANCE <nom-app>" → publication（compte Google Play requis ici）。

## Ce que l'utilisateur n'a JAMAIS à fournir
Les captures d'écran des concurrents, métadonnées, avis ：les agents les téléchargent
seuls（DÉCORTIQUE。. Fournitures OPTIONNELLES mais précieuses ：captures d'écran
personnelles des MENUS internes d'un concurrent（ce que les stores ne montrent pas）,
et toute note"j'aime / j'aime pas" sur un concurrent。
